# FRED catalog design diagrams

Generated by MATLAB. Do not edit the `.dot`, `.png` or `.svg` files by hand.

| File | View |
|---|---|
| `fred_logical_design` | Logical design: relations, PK underlined, FK italic, derived attributes in [brackets], Hoffer weak/associative borders |
| `fred_fd_maps` | Functional dependency map per relation in the course notation (key box, arrow to each dependent); all-key relations in a note. HW 3/4 material |
| `fred_table_map` | The relations as records: PK underlined, FK columns tagged, an arrow from each FK to the key it references |
| `fred_physical_postgresql` | Physical design for PostgreSQL 16: stored types, NULL/defaults, named constraints, indexes, triggers and routines |
| `fred_physical_mysql` | Physical design for MySQL 8 / MariaDB: same template, with `` `release` ``, INT/TINYINT(1), implicit InnoDB FK indexes and `add_vintage()` |
| `fred_neo4j_logical` | Neo4j logical design: labels, properties, directed relationship types in three layers (catalog, press releases, lineage); each label and edge names the table or FK it came from, and the legend lists the full relational-to-graph conversion |
| `fred_neo4j_physical` | Neo4j physical design: stored Cypher types, required/optional, uniqueness constraints, RANGE/FULLTEXT/VECTOR indexes, Community-edition limits, and every type difference from SQL |

## Rebuild

From `src/` in MATLAB:

```matlab
build_fred_design_diagrams()                          % checks DDL files + live PostgreSQL + live Neo4j
build_fred_design_diagrams(CheckLiveDatabase=false)   % DDL files only
```

## How it fits together

- `src/+dbdesign/fred_relational_model.m` describes the relational schema; `src/+dbdesign/fred_graph_model.m` describes the graph and maps every label and relationship back to a table or FK (Neo4j's table-to-graph checklist).
- Before drawing anything, the build compares the models with `sql/fred_schema.sql`, `sql/mysql/fred_schema.sql`, the live `fred` database and the live Neo4j graph (HTTP API), and stops on any difference. It also checks that every SQL table and FK has a place in the graph, or is listed as excluded (OBSERVATION).
- The Neo4j password comes from `NEO4J_PASSWORD`, else the MATLAB vault secret `neo4j_pw`.
- `src/+dbdesign/write_schema_dot.m` (relational), `write_fd_dot.m` (FD map and table map) and `write_graph_dot.m` (graph) are the templates; `src/+dbdesign/physical_type.m` maps declared types to the types each DBMS stores.
